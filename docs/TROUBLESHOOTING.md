# API 配置故障排查：401、403、404、429 与连接失败

[返回首页](../README.md) · [快速开始](QUICKSTART.md) · [密钥安全](../SECURITY.md)

先记录客户端、版本、操作系统、请求时间和脱敏后的状态码。不要把完整 API Key、配置文件、认证头或请求正文提交到公开 Issue。

| 症状                       | 优先检查                                       | 下一步                                              |
| -------------------------- | ---------------------------------------------- | --------------------------------------------------- |
| 401 Unauthorized           | Key 是否缺失、失效、含空格，是否属于当前服务商 | 从对应控制台核对凭据；必要时撤销并重新创建          |
| 403 Forbidden              | 模型权限、账户限制、网关访问策略               | 查服务商日志与权限，不要把它一律解释为余额不足      |
| 404 Not Found              | Base URL 和协议是否匹配，是否重复 `/v1`        | 对照客户端配置指南；部分服务商也可能用 404 隐藏资源 |
| 429 Too Many Requests      | 速率限制、并发、额度或容量                     | 按服务商响应与文档等待或降低并发；不要无限快速重试  |
| 超时、DNS、TLS 错误        | 域名、网络、代理、证书                         | 先检查连接，不要通过关闭 TLS 校验掩盖问题           |
| 模型列表有结果，但请求失败 | 模型 ID、权限、请求协议                        | 对目标模型执行实际客户端验证                        |
| 导入后仍走旧 API           | CC Switch 激活状态、旧终端、环境变量覆盖       | 激活服务商并重启终端或客户端                        |
| 点击导入没有打开 CC Switch | 是否已安装、是否注册链接协议                   | 回到环境检查；也可展开手动配置                      |
| Codex 配置异常             | 模板是否覆盖了原有定制项                       | 查看自动备份，确认后恢复，不要删除整个配置目录      |

## 快捷模式不能代替环境检查

「直接配置 API」会跳过安装和检查。若提示找不到 `codex`、`claude` 或 CC Switch，返回「先检查环境」，不要把网络测试通过当作客户端已安装。

## 测试结果如何解读？

一次成功只证明当时、该地址、该模型、该 Key 对应的请求成功。修改地址、模型或 Key 后应重新测试；应用会清除旧的连接结果，避免误认为新配置已验证。

## 提交问题时提供哪些内容？

- 操作系统和应用版本。
- 选择的客户端、完整流程或快捷模式。
- 最少复现步骤、期望结果、实际结果。
- 脱敏后的错误码；截图前检查 URL 参数、Key、账户和路径。

[提交 GitHub Issue](https://github.com/easyrouter/llm-api-tutorial/issues/new/choose)。疑似凭据泄露先在服务商处撤销 Key，不要等待他人回复。
