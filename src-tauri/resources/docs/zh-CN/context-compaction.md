# 上下文与自动压缩

这一页解释[配置](wizard://configure)页上"Codex config.toml 模板（推荐）"卡片里的"上下文与自动压缩"：上下文窗口是什么、Codex 什么时候自动压缩、模板写了什么，以及在 CC Switch 里要注意什么。只用 Claude Code 的话可以跳过这一页。

## 基本概念

- **上下文窗口**：Codex 每次请求都会把说明文件（如 `AGENTS.md`）、之前的对话和命令输出一起发给模型。模型一次能装下的总量叫"上下文窗口"，按 token（模型计算文字量的单位）计算。
- **自动压缩**：快装满时，Codex 会自动"压缩"——把较早的内容换成一份交接摘要，保留你最近发的消息，然后接着干活。较早的细节会丢掉一些。
- 自动压缩一直开着，**无法关闭**。能调的只有窗口多大、什么时候压缩。

## 推荐设置：OpenAI 默认

卡片默认使用"OpenAI 默认（推荐）"。这时**模板不写任何上下文设置**：`model_context_window`、`model_auto_compact_token_limit`、`model_auto_compact_token_limit_scope` 三项都不写。Codex 于是使用 OpenAI 为 `gpt-6-astra`、`gpt-6.1-sol`、`gpt-5.6-sol` 设定的默认值：

- 上下文窗口 **272K**（272,000 token）；
- 用到窗口的 90%，即约 **245K** 时自动压缩；
- 用到 95%，即约 **258K** 时一定会压缩，`/status` 里显示的窗口大小也是这个数；
- 统计口径 `total`（统计对话里的全部内容）。

为什么推荐它：

- **这是 OpenAI 的默认值。** OpenAI 没有公布其他推荐数字。OpenAI Codex 团队成员在社交媒体上表示，这个默认值是按效果和成本仔细调过的（个人发言，说的是 ChatGPT 订阅下的 GPT-5.6 Sol，不是官方文档）。
- **请求一般不会超过 272K。** 按 OpenAI 官方价格，输入超过 272K 的请求整单加价：输入和缓存按 2 倍、输出按 1.5 倍计费。服务网关对这类请求怎么计费，目前还没有确认。Codex 在每轮开始前检查用量，但不计入你这次要发的消息，所以在已经很长的对话里粘贴特别长的内容，仍可能让这一次请求（以及紧接着的压缩请求）超过这些数字——要粘贴大段日志时，先输入 `/compact` 再粘贴。
- **窗口越大越贵。** 每一轮都要把上下文重新发送一遍。窗口越大，每轮发送的内容越多，即使单价不变也更贵。
- **最不容易超出服务网关的限制。** 服务网关没有公布每条线路实际能接受多长的请求。这是可选设置里最小的窗口，最有可能每条线路都放得下。请求太长时，可能会以一种只有新开对话才能解决的方式失败。
- **CC Switch 没有东西可丢。** 模板不写这些设置，CC Switch 切换供应商时也就不会把它们弄丢，或者带到别的供应商上。

## 大窗口（只有 IT 开启后才会出现）

大多数人在卡片上只会看到"OpenAI 默认（推荐）"。只有 IT 确认服务网关的每一条线路都能接受更长的请求、并在公司预设里开启之后，卡片上才会多出"大窗口（适合长任务）"。它只对 GPT-6、GPT-5.6 系列模型出现：其他模型（例如 `gpt-5.5`）在 Codex 里最多只按 272K 处理，写了也没有用。选中它，模板会写入（数字以卡片上显示的为准）：

```
model_context_window = 372000
model_auto_compact_token_limit = 300000
model_auto_compact_token_limit_scope = "total"
```

也就是：上下文窗口 **372K**，用到 **300K** 时自动压缩，最晚在约 **353K** 时一定会压缩。

- **适合**：一个任务要连续做很久的情况。压缩次数更少，等压缩的时间也更少。
- **代价**：每轮发送的内容更多，所以更贵；按 OpenAI 官方价格，输入超过 272K 的请求还会整单加价。服务网关怎么计费，以 IT 的说明为准。
- **长对话开始反复出错时**（例如提示上下文太长）：回到"配置"页选回"OpenAI 默认（推荐）"，再点一次"一键应用到本机 Codex"，然后新开一个对话。在出错的对话里重试没有用。

## 这些配置项分别是什么意思

本工具写入的模板里最多只会出现前三项，而且只在选了"大窗口"时才写。其余几项列在这里，供自己编辑 `config.toml` 的人参考；一般保持不设即可。

### `model_context_window`（上下文窗口）

Codex 认为模型一次能容纳多少内容，单位是 token。不写时用 272K。Codex 只把其中 95% 当作可用空间，用到这里一定会压缩。数值越大，压缩越少，但每条消息越贵；而且绝不能超过服务网关实际能接受的长度，否则长对话会出错。写得再大，对这几个模型 Codex 最多也只按 872K 处理。

### `model_auto_compact_token_limit`（自动压缩阈值）

对话累计到这个 token 数时，Codex 自动压缩。不写时是窗口的 90%（默认约 245K）。统计口径为 `total` 时，写得比 90% 还大也只按 90% 算。数值越小，压缩越频繁：单条消息更省钱，但丢的细节更多。无论怎么设，用到窗口的 95% 时都会压缩。

### `model_auto_compact_token_limit_scope`（统计口径）

- `total`：默认值，也是本工具唯一会写的值。统计对话里当前的全部内容：系统指令、`AGENTS.md`、上次压缩的摘要和之后的所有消息。达到设定的数字就压缩，行为最可预测。
- `body_after_prefix`：只统计"当前这一段对话"开始之后新增的内容——从会话开始、上次压缩或恢复对话时算起，包括第一次回答。之前带进来的指令、`AGENTS.md` 和上次的摘要都不计入。它是为"较小的增量预算"设计的；阈值较大时，它只会把压缩推迟到窗口用到约 95% 时，留下的余地很小。

这个选项**和提示词缓存（prompt caching）没有任何关系**，也不会"更准确"。本工具早期版本把 `body_after_prefix` 标为"推荐"，并解释成"只统计缓存前缀之后的会话正文……配合提示词缓存更准确"。这个说法是错的，现已删除。

### `compact_prompt` / `experimental_compact_prompt_file`（摘要怎么写）

写压缩摘要时使用的指令，只对本地压缩生效。内置版本已经要求写清进度、决定、约束和下一步。请保持不设；指定的文件不存在或为空时，Codex 会无法启动。

### `tool_output_token_limit`（单条命令输出上限）

一条命令的输出在对话里最多保留多少，超出的部分从中间截掉。保持默认即可；调大会更快占满上下文。

### `features.context_management.experimental_mode`（实验功能）

GPT-6 Astra 发布时宣布的"跨上下文窗口笔记"（notes across context windows）实验功能。OpenAI 的配置文档写明它目前不可用；而且它只适用于用 ChatGPT Plus / Pro 等付费账号登录、直接使用 OpenAI 服务的情况，通过服务网关或 API Key 使用时永远用不上。请不要开启。

## 本地压缩和远程压缩

Codex 有两种压缩方式。对服务网关这样的自定义供应商，用哪一种主要取决于 `config.toml` 里供应商的名称（`[model_providers.…]` 下面的 `name`）：

- **本地压缩**：同一个模型通过服务网关写一份纯文本的交接摘要。任何服务网关都能用。本工具的模板用的就是这种。
- **远程压缩**：名称恰好是 `OpenAI`（大小写完全一致），或者是 `azure`（不论大小写）时使用；地址是 Azure 的地址（例如含有 `openai.azure.`、`azure-api.`、`azurefd.`）时也会使用。压缩结果是一段加密内容，换到别的上游账号可能就读不出来，而服务网关背后有多个上游；服务网关是否支持也没有确认，失败时没有退路。

所以请保留模板里的供应商名称（例如"服务网关"），不要改成 `OpenAI`。本工具不会使用这两种名称：即使你在"要填写的值"里这样填，生成的模板和"一键导入 CC Switch"都会自动改用别的名称（导入前的预览里能看到实际发送的名称）。

## 在 CC Switch 里要注意的

下面的选项都在 CC Switch 的 Codex 标签页、编辑供应商的表单里："1M 上下文窗口"、"启用远程压缩"、"应用通用配置"、"编辑通用配置"在"config.toml (TOML)"一栏附近，"模型映射"在"高级选项"里。名称按 CC Switch v3.20.4 写，新版本可能略有不同。

- **不要勾选"1M 上下文窗口"。** 勾选后会写入 `model_context_window = 1000000` 和 `model_auto_compact_token_limit = 900000`，Codex 实际按 872K 处理：远超推荐值，更贵，也可能超出服务网关能接受的长度。取消勾选会把这两行一起删掉。
- **不要勾选"启用远程压缩"。** CC Switch 自己的说明是"开启后会将当前 model_providers 条目的 name 写为 OpenAI，使 Codex 尝试使用远程压缩"。经服务网关转发时，远程压缩可能失败，或让长对话无法继续。
- **不要把上下文设置放进通用配置。** "编辑通用配置"里的片段会合并进每一个勾选了"应用通用配置"的供应商，而且片段里的值会盖过供应商自己的设置。
- **切换供应商会重写 `config.toml`。** 在 CC Switch 里切到别的供应商时，它通常会重写 `~/.codex/config.toml`；切回原来的供应商时一般会恢复。如果"配置"页卡片显示"与模板不同"，再点一次"一键应用到本机 Codex"即可。
- **"统一供应商"会用固定模板重写。** 如果你用的是 CC Switch 的"统一供应商"，并且它正是当前使用的供应商，每次"同步到应用"或"保存并同步"，CC Switch 都会用它自己的固定模板重写 `config.toml`。同步之后请再点一次"一键应用到本机 Codex"。
- **尽量不要添加"模型映射"。** 如果一定要加，请在每一行的"上下文窗口"列填 `272000`（用大窗口时填 `372000`）。在推荐设置下这一列留空，CC Switch 会告诉 Codex 这个模型的窗口只有 128K，压缩会早得多。映射行还会让 priority 档位失效。

### 用过早期版本，或复制过 372000 的配置？

本工具早期版本会把 `372000`、`300000`、`body_after_prefix` 写进 `~/.codex/config.toml`，有些教程里也写着 `372000`。这个数字来自 GPT-5.6 Sol 刚发布时 Codex 里的设置，OpenAI 随后已把它更正为 272,000。CC Switch 可能已经把这些设置抄进了供应商的配置或通用配置里，切换供应商时又会写回去。请这样清理：

1. 在 CC Switch 里编辑你正在使用的 Codex 供应商，在"config.toml (TOML)"编辑框里删掉 `model_context_window`、`model_auto_compact_token_limit`、`model_auto_compact_token_limit_scope` 这几行；
2. 点"编辑通用配置"，同样检查并删掉这几行；
3. 保存；
4. 回到本工具"配置"页，再点一次"一键应用到本机 Codex"。如果本机文件里还有这些旧设置，卡片会提示；应用后会换成卡片上所选策略的设置（默认就是全部删掉）。

## 好习惯

这些习惯比任何数字都管用：

- **每个独立任务新开一个对话**（Codex 客户端或 IDE 扩展里新建对话，CLI 里输入 `/new`）。Codex 自己也提示：对话太长、压缩次数太多会让回答不准确。
- **在自然节点主动压缩**：功能做完、测试通过时输入 `/compact`，不要等任务做到一半被自动压缩。要在很长的对话里粘贴大段日志前，也先 `/compact`。
- **用 `/status` 查看**剩余上下文（CLI 里还会显示模型和供应商）。默认设置下窗口显示约 258K；还没用完就压缩属正常现象。
- **把计划写进文件**：计划、决定和进度写进仓库里的文件（如 `PLAN.md`、`NOTES.md`），并让 Codex 随时更新。压缩只留摘要，文件不会丢。
- **`AGENTS.md` 尽量精简**（Codex 最多读取 32 KiB），关闭不用的 MCP 服务和技能——它们每条消息都占上下文。
- **临时小问题用 `/side`**，只有工作真正分岔时才用 `/fork`。
- **长对话中途不要切换模型、工具或沙箱模式**：会让缓存失效（更贵），也可能干扰压缩。
- **改完设置新开对话**：修改 `config.toml` 或在 CC Switch 切换供应商后，请新开一个对话；已经打开的对话仍用旧设置。

## 常见问题

**还没到上面的数字就压缩了？**
正常。Codex 估算用量时，有时会把模型之前的推理过程也算进去，所以压缩可能比数字明显提前，有时提前几万 token。在 OpenAI 自家的服务上也有人遇到同样的情况。

**压缩之后，它好像"忘了"之前说过的事？**
压缩只留下一份摘要和你最近发的消息，较早的细节会丢掉一些，这是压缩本来的样子。把关键要求再说一遍，或者写进文件（如 `PLAN.md`）让它去读；对话已经很长时，新开一个对话并贴上要点。

**反复提示上下文太长、对话无法继续？**
新开一个对话并贴上要点，在原对话里重试没有用。如果你自己在 `config.toml` 里写过 `model_context_window`，或者选了"大窗口"，回到"配置"页选"OpenAI 默认（推荐）"，再点一次"一键应用到本机 Codex"，这些设置就会被去掉（CC Switch 里也写过的话，按上面"用过早期版本"一节清理）。仍然出现请联系 IT。

**改了设置，什么时候生效？**
新开一个对话就生效，已经打开的对话仍用旧设置。如果 Codex 桌面应用的模型列表或登录状态没有更新，请彻底退出它（包括托盘图标）再重新打开。

**Windows 上的 Codex 桌面应用在 WSL 模式下运行？**
这时它读取的是 WSL 里的 `~/.codex/config.toml`，不是本工具写入的 Windows 文件，所以这里的设置对它不起作用。需要帮助请联系 IT。
